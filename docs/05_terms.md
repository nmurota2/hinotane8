# データ利用規約の制約（J-Quants API）

このシステムは J-Quants API（株式会社JPX総研）のデータで動いている。
規約の一部は **設計上の制約** になっているので、ここにまとめておく。
コードを触るときは必ず読むこと。

参照: J-Quants APIサービス利用規約（最終改定 2026-01-19）

---

## 1. 私的使用に限られる（第8条）

> 本サービス及び本データの利用目的は、登録ユーザーのみによる私的使用の目的に限ります。
> 本データ（本データを編集又は加工したものを含みます）を、第三者が使用できる状態にすること
> （インターネット上での配信を含みます）または商用もしくは学術の目的で利用することは、
> 私的使用の目的に該当しません。

**「編集又は加工したもの」を含む**という点が重要。
株価そのものを配れば違反なのは当然として、株価から作ったシグナル・スコア・
チャート・銘柄リストも「加工したもの」に当たると読むべき。

| やること | 可否 |
|---|---|
| 自分が LINE で銘柄提案を受け取り、自分の口座で売買する | ✅ |
| 通知を家族・友人に転送する | ❌ 第三者が使用できる状態にすること |
| 同じ LINE Bot を他人にも使わせる | ❌ 同上 |
| シグナルをブログ・SNS・掲示板に載せる | ❌ インターネット上での配信 |
| 銘柄提案を有料で売る／投資助言サービスにする | ❌ 商用（金商法上も別途問題） |
| 研究発表・論文に使う | ❌ 学術目的 |

### これがコードに効いているところ

* **`LINE_ALLOWED_USER_IDS` のホワイトリスト**（`webhook.py`）
  セキュリティのためだけではなく、**規約を守るための仕組み**でもある。
  ここを空にしたり「誰でも登録できる」ようにしたりしてはいけない。

* **Webhook の署名検証**
  外部から勝手にリクエストを投げてシグナルを引き出せる状態は、
  実質的に「第三者が使用できる状態」になる。

* **Webhook サーバーを公開する場合**
  URL を知られても、userId が一致しない相手には何も返さないこと。
  シグナルの内容を GET で引ける URL を作らないこと。

## 2. 契約を終えたらデータを消す（第7条・第15条第5項）

> サブスクリプションをキャンセルし現在の残りの請求対象期間が終了した後、
> ただちに本データ及びその複製物を全て廃棄若しくは消去しなければなりません。

> 退会にあたり、登録ユーザーは、ただちに本データ及びその複製物を全て廃棄等しなければなりません。

**消すもの**: `hinotane.duckdb`、そのバックアップ、他の場所にコピーした CSV など。

## 3. プランを下げたあとのデータ保持は、規約に書かれていない

第6条第6項は「プランの変更」を「キャンセル」とは別に定めている（日割り計算、
同月内の下位プランへの変更は1回まで）。したがって第7条の削除義務は、文言上は
ダウングレードにかからないと読むこともできる。

ただし:
* 第2条(7) 本データは「**貸与**する」データと定義されている
* 第17条(6) JPX には利用状況を**調査する権利**がある

**規約はこの場合を明示していない。** 「上位プランで長期データを取り込んでから
下位プランに落として使い続ける」という運用を前提に計画を立てないこと。
必要なら J-Quants の Support に直接確認する。

## 4. API キーは自分だけのもの（第5条）

> パスワード、ユーザーID及びAPIキーを適切に管理及び保管するものとし、
> これを第三者に利用させ、または貸与、譲渡、名義変更、売買等をしてはならない。

* キーは `.env` にだけ置く（`.gitignore` 済み・`chmod 600`）
* **コミットしない・チャットに貼らない・スクリーンショットに写さない**
* `doctor` などの診断表示は、長さと先頭4文字・末尾4文字までに留めてある

## 5. 過度な負荷をかけない（第11条第1項(5)）

`config.py` の `requests_per_min` と `rate_safety_margin`、
`jquants.py` の `RateLimiter`（429 で自動的に間隔を広げる）はこのための仕組み。
**取得を速くしたいからといって、レート制限を外したり無視したりしないこと。**
契約プランの上限を超える値を `JQUANTS_REQUESTS_PER_MIN` に入れないこと。

## 6. データの正しさは保証されない（第17条(3)）

> 当社及びデータ提供会社は、本データの真実性、正確性、信用性、有用性及び
> 登録ユーザーが本データを用いて行う判断の一切について責任を負うものではありません。

株価が間違っていても誰も責任を取らない。**発注前に必ず人間が承認する**という
設計（LINE で「買う／見送る」をタップするまで発注しない）は、ここへの備えでもある。
`LIVE_TRADING=false` を既定にしてあるのも同じ理由。
